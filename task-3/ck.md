# CK

https://github.com/mauricioaniche/ck

## Описание программного анализатора

CK вычисляет метрики кода на уровне классов и методов в Java-проектах с помощью статического анализа. В настоящее время он содержит большой набор метрик, включая знаменитый CK:

* CBO (Coupling between objects): Подсчитывает количество зависимостей, которые есть у класса. Инструмент проверяет наличие любого типа, используемого во всем классе (объявление поля, возвращаемые типы методов, объявления переменных и т.д.). Высокий CBO - признак плохой модульности.

* CBO Modified (Coupling between objects): Подсчитывает количество зависимостей, которые имеет класс. Это очень похоже на исходный CBO. Однако этот показатель рассматривает связи через поля класса: если класс A имеет поле типа класса B, то есть связь между классами. Связи являются двунаправленными - если класс A ссылается на B, а B ссылается на A, это считается как одна связь.

* FAN-IN: Подсчитывает количество входных зависимостей, которые есть у класса, т.е. количество классов, использующих данны определенный класс.

* FAN-OUT: Подсчитывает количество выходных зависимостей, которые есть у класса, т.е. количество других классов, которые используют данный класс.

* DIT (Depth Inheritance Tree): Подсчитывает длину пути от класса до самого корневого класса в иерархии наследования.

* NOC (Number of Children): Подсчитывает мисло непосредственных подклассов (детей) у данного класса.

* Number of fields: Подсчитывает количество полей в классе.

* Number of methods: Подсчитывает количество методов в классе.

* Number of visible methods: Подсчитывает количество видимых методов в классе (то есть не приватных).

* NOSI (Number of static invocations): Подсчитывает количество вызовов статических методов

* RFC (Response for a Class): Подсчитывает количество уникальных методов, которые могут быть вызваны при вызове метода этого класса

* WMC (Weight Method Class) or McCabe's complexity: Подсчитывает сумму цикломатической сложности всех методов класса.

* LOC (Lines of code): Подсчитывает количество строк кода в классе.

* LCOM (Lack of Cohesion of Methods): Подсчитывает степень, в которой методы класса связаны друг с другом через использование общих полей.

* LCOM* (Lack of Cohesion of Methods): усовершенствованная версия метрики LCOM, выдает значения от 0 до 1, где 0 - идеальная связность, а 1 - отсутствие связности.

* TCC (Tight Class Cohesion): Подсчитывает процент пар public методов класса, которые связаны через использование хотя бы одного общего поля.

* LCC (Loose Class Cohesion): Похожа на TCC, но учитывает также косвенные связи (через третьи методы)

* Quantity of returns: Подсчитывает количество возвратов из методов класса.

* Quantity of loops: Подсчитывает количество циклов в классе.

* Quantity of comparisons: Подсчитывает количество сравнений в классе.

* Quantity of try/catches: Подсчитывает количество try/catch блоков в классе.

* Quantity of parenthesized expressions: Подсчитывает количество выражений в скобках в классе.

* String literals: Подсчитывает количество строковых литералов в классе.

* Quantity of Number: Подсчитывает количество числовых литералов в классе.

* Quantity of Math Operations: Подсчитывает количество математических операторов в классе.

* Quantity of Variables: Подсчитывает количество переменных в классе.

* Max nested blocks: Подсчитывает максимальную глубину вложенности блоков кода внутри класса.

* Quantity of Anonymous classes, inner classes, and lambda expressions: Подсчитывает количество анонимных классов, вложенных классов и лямбда выражений в классе.

* Number of unique words: Посчитывает количество уникальных слов в исходном коде.

* Number of Log Statements: Подсчитывает количество log-вызовов в исходном коде.

* Has Javadoc: Boolean, указывающий, есть ли в классе javadoc.

* modifiers: public/abstract/private/protected/native modifiers of classes/methods.

* Usage of each variable: Подсчитывает как часто каждая переменная использовалась внутри каждого метода.

* Usage of each field: Подсчитывает как часто каждое локальное поле использовалось внутри каждого метода. Локальное поле (local field) — это поле (атрибут), определенное непосредственно в данном классе, в отличие от унаследованных полей от родительских классов.

* Method invocations:  Подсчитывает количество прямых вызовов методов.
